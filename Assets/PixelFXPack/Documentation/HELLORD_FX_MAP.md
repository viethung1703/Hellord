# Hellord v0.2 prototype hooks -> Pixel FX Pack map

Latest version: v2.3.1 (SkillFX #132-136 hero skills: Fireball / Frost Cleave / Storm Ring / Bone Orbit / Curse Rune with a shared white-core + silver-rim hero signature; v2.0.1 PickupFX SetDropSprites for HA blood/bone pickups; 136 effects; compile-checked, nothing tested in the Unity Editor). Skill hooks: Fireball cast/move/impact -> SkillFX.FireballSpawn/Move/End (replaces ProjectileFX Fire visuals); Frost Cleave swing -> SkillFX.FrostCleave (instead of HFX.FrostCleave); Storm aura -> SkillFX.StormRing per frame + StormTick/StormArc per tick (instead of HellFX.AuraField + ChainLightningPoints); Bone Orbit -> SkillFX.BoneOrbit per frame + BoneHit; Curse Rune -> SkillFX.CurseRune (+OnRuneBurst) + CurseMark. Level = skill level 1-5.
Packages: `/workspace/PixelFXPack/PixelFXPack-v1.8.9.unitypackage` and `/workspace/PixelFXPack/PixelFXPack-v1.8.9.zip`. Not run in the Unity Editor and no FPS measured yet.
All APIs are in `namespace PixelFXPack`. Positions are world space and sizes are art pixels. Set `HellFX.PPU` (default 16) to your sprite PPU **before** the first ChainFX/ReactionFX/TellFX call. Production status per MM row: see `HELLORD_FX_PLAN.md`.

v1.7.1: enemy telegraph defaults (#101/#102/#103/#108 tell) are `TellFX.TellRed` = #e43b44 (ground mark) and `TellFX.TellHot` = #feae34 (flash core). Pass `color` to override the ground mark.

## Global setup (do once, at scene load)
```csharp
HellFX.PPU = 16f;                         // ChainFX builds its atlas from this; rebuilt only if PPU changes
HordeFX.I.pixelsPerUnit = 16f;
ChainFXRunner.I.Prewarm();                // creates 48 x 32 = 1536 inactive SpriteRenderers up front
ReactionFXRunner.I.Prewarm();             // creates 48 x 48 = 2304 inactive SpriteRenderers up front
ReactionFXRunner.StatusCap = 32;          // shared cap for live Shock + Bleed + Burn + Chill statuses (clamped to 48)
TellFXRunner.I.Prewarm();                 // v1.8: creates 48 x 48 = 2304 inactive SpriteRenderers up front
TellFX.OnTellFire = (int handle, int index) => { /* optional: tell resolved -> run your hit test */ };
var _ = ProjectileFXRunner.I;             // touching I creates all 1024 projectile SpriteRenderers in Init()
ProjectileFX.OnHit = (Collider2D col, float dmg, ProjElement el) => { /* damage */ };
ProjectileFX.FindTarget = MyFinder;       // delegate bool TargetFinder(Vector2 from, float radius, out Vector2 target) - keep it allocation-free
ProjectileFX.ShakeScale = 1f; ProjectileFX.HitStopScale = 1f; ProjectileFX.FlashScale = 1f; // global juice scales
```
Enemies need a `Collider2D` (triggers OK) for ProjectileFX, ChainFX and ReactionFX hits. For batched flash and death, call `HordeFX.Prepare(sr)` on each enemy.

Other perf notes:
- Every projectile and every whip runs a `Physics2D.OverlapCircle` check per frame, which costs CPU at around 1000 projectiles.
- ProjectileFX sprites batch per element, not across elements (one texture per element/frame). ChainFX uses one atlas, so all three of its effects batch together; ReactionFX likewise uses one atlas for all six.
- ReactionFX Shock/Bleed and v1.7 StatusFX Burn/Chill statuses are separate pooled sprites and keep HordeFX batching. Status shaders (Burn/Frozen/Pulse) still need the per-sprite `PixelFX` Uber material and break HordeFX batching, so apply them only to elites/bosses or a capped number of enemies.

> v1.8.0: Burn/Chill now tint the target `SpriteRenderer.color` (restored on end; `StatusFX.TintTargets=false` to disable) and no longer copy the sprite, so batching is kept. If Hellord sets `SpriteRenderer.color` (e.g. hit flash via color), disable tinting or let the hit flash use the material. PunishGlow/BloodrageTrail need a SpriteRenderer on the boss for the outline (ring fallback otherwise).
> v1.7.1 polish (superseded for Chill): ChillStatus outline needs a SpriteRenderer on the target (child ok) and may break batching if enemies use a custom material; Stampede `color` now tints only the oxen.

## UI rule: damage numbers (v1.8.3)
1. One number per target per burst: hits on the same target add to one rising total until 0.4s passes with no hit, then it fades. Crits bump that total (yellow + brief pop), never a separate or 'x2' number (`HordeFX.Hit` does this per SpriteRenderer; for custom calls use `HordeFX.Number(pos, value, crit, target.GetInstanceID())`).
2. Layout: a new number is tested against the bounding boxes of all live numbers (whole rise path); it moves up/sideways to a free slot, or is dropped. Never overlap.
3. Short life: 0.5s normal, 0.75s crit; crits pop 2x for 1-2 frames only.
4. Boss numbers anchor above the head, not on the body, so they never cover tells or the stun stars.
5. Impact frames are the boss's own silhouette (at most 1.04x): a single white frame (no black frame: it reads as a black hole on dark arenas), never a screen-wide flash. Regular hits use a 1-frame flash, not an impact frame.
6. Damage numbers sit on a dark backing plate and are laid out clear of drops, pops and hit sparks.
